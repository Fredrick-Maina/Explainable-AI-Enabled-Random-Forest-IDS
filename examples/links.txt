INSTRUCTIONS TO RUN

 The best and most reliable way to run this project is to use the existing Python
  virtual environment (venv) to keep all your dependencies (like shap, scikit-learn,
  scapy, etc.) isolated and clean.

  Because Intrusion Detection Systems require elevated privileges to sniff network
  traffic on your network interfaces, you'll need to run the final script as root
  (using sudo). However, using sudo normally resets your Python environment, so we have
  to point it explicitly to your virtual environment's Python binary.
  Here is the step-by-step best practice for running it:

  ### 1. Activate the Virtual Environment & Install Dependencies

  First, make sure your virtual environment is active and up to date:
    # Activate the virtual environment
    source venv/bin/activate
    
    # Install all required packages (including the new SHAP library)
    pip install -r requirements.txt
    
  ### 2. Train the AI Model (If you haven't already)
  Before the IDS can classify traffic, it needs a trained model in the models/
  directory. Since you're running this locally, you can kick off the training script.
  Note: You do not need sudo for training.

    python3 src/ml/train.py
    
  (If it doesn't find the real dataset in the data/ folder, it will automatically
  generate synthetic data and train a prototype model so you can test it).

  ### 3. Run the Main Hybrid IDS
  To actually start sniffing network traffic and analyzing it with your AI model + SHAP
  explainer, you need root privileges. To do this while keeping the virtual
  environment's dependencies, you specify the direct path to the venv python:

    sudo venv/bin/python main.py

  (Optionally, you can specify an interface like sudo venv/bin/python main.py eth0 or
  wlan0)

  ### 4. Monitor the Output

  While it's running, you'll see the live output in your terminal. For historical
  records or if you run it in the background, you can always check the logs:

  • System Logs: tail -f logs/system.log
  • Security Alerts (with SHAP explanations!): tail -f logs/alerts.log
